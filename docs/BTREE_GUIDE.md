# B-дерево для лабораторной работы

Задача — самостоятельно реализовать упорядоченный словарь `слово → uint64_t` на B-дереве. Этот конспект объясняет устройство дерева и алгоритмы; протокол команд, файлы и память разобраны в [проектировании словаря](DICTIONARY_DESIGN.md).

## 1. Связь с уже знакомыми структурами

В `ADAL/homework1/E_bst/solution.cpp` есть treap, в `ADAL/homework2/B_rate_limiter/solution.cpp` — treap со статистикой, в `ADAL/seminars/3sem/.cpp` — красно-чёрное дерево, в `ADAL/seminars/5sem/.cpp` и `ADAL/homework2/G_search_suggestions/solution.cpp` — бор.

Общая идея с деревом поиска сохраняется: сравнение ключей определяет, в какое поддерево идти. В B-дереве один узел содержит несколько упорядоченных ключей и несколько детей.

| Структура | Что хранится в узле | Как поддерживается высота |
| --- | --- | --- |
| Обычное BST | Один ключ | Без балансировки может выродиться в цепочку |
| Treap | Ключ и случайный приоритет | Ожидаемая логарифмическая высота при обычных предположениях о случайных приоритетах |
| Красно-чёрное дерево | Один ключ и цвет | Инварианты цветов, повороты и перекрашивание |
| B-дерево | Несколько ключей и массив детей | Ограничения заполнения, одинаковая глубина листьев, разделения и слияния |
| Бор | Переходы по буквам | Путь определяется символами, а не сравнением целых слов |

`split` в treap делит целое дерево по значению ключа. `splitChild` в B-дереве разделяет один заполненный узел вокруг его среднего ключа. Это разные операции.

В B-дереве хранятся полные пары «ключ, значение» и в листьях, и во внутренних узлах. Здесь рассматривается обычное B-дерево. В B+ дереве записи обычно сосредоточены в листьях; его алгоритмы не следует смешивать с алгоритмами этой ЛР.

## 2. Инварианты

Пусть `t >= 2` — минимальная степень. Пользуемся обозначениями, в которых максимум детей равен `2t`. В других источниках «порядком m» могут называть максимальное число детей; в этой системе обозначений `m = 2t`. Перед использованием формул нужно сверить определение параметра.

1. Ключи внутри узла строго возрастают: `k[0] < k[1] < ... < k[m-1]`.
2. У внутреннего узла с `m` ключами ровно `m + 1` детей. У листа детей нет.
3. Поддеревья разделяются ключами узла:
   - в `child[0]` все ключи меньше `k[0]`;
   - в `child[i]` все ключи между `k[i-1]` и `k[i]`;
   - в `child[m]` все ключи больше `k[m-1]`.
4. Все листья находятся на одной глубине.
5. Любой узел, кроме корня, содержит от `t - 1` до `2t - 1` ключей.
6. Непустой корень содержит от `1` до `2t - 1` ключей. Если он внутренний, у него хотя бы два ребёнка.

Пустой словарь удобно представлять пустым листом-корнем. Допустим и `root == nullptr`, но тогда это отдельный случай в алгоритмах. Не нужно одновременно использовать оба представления без необходимости.

**Внутренний** означает «имеющий детей», **некорневой** означает «не являющийся корнем». Ограничение `t - 1` относится и к некорневым листьям.

Например, при `t = 2`:

```text
                  [10 | 20]
                 /    |    \
          [5 | 7] [12 | 17] [30]
```

У корня два ключа и три ребёнка. Все листья находятся на глубине один. В левом листе ключи меньше 10, в среднем — между 10 и 20, в правом — больше 20.

Для схем используются числа, чтобы было проще следить за перестройками. В программе сравниваются нормализованные слова.

| t | Минимум ключей вне корня | Максимум ключей | Максимум детей |
| --- | ---: | ---: | ---: |
| 2 | 1 | 3 | 4 |
| 3 | 2 | 5 | 6 |
| 16 | 15 | 31 | 32 |
| 32 | 31 | 63 | 64 |

Для ручных примеров и отладки полезен `t = 2`: перестройки происходят часто. Для рабочей программы степень выбирают по измерениям. Число `4` в названии присланного варианта само по себе не означает `t = 4`.

Определения и стандартные операции можно сопоставить с [лекционными материалами SDSU](https://eli.sdsu.edu/courses/fall96/cs660/notes/redBlack/redBlack.html).

## 3. Почему высота логарифмическая

Пусть `h` — число рёбер от корня до листа, `n >= 1` — число ключей. Минимум ключей при данной высоте получается так:

- в корне один ключ;
- если `h >= 1`, на первом уровне два узла;
- далее каждый внутренний некорневой узел имеет хотя бы `t` детей;
- каждый некорневой узел содержит хотя бы `t - 1` ключей.

Поэтому

```text
n >= 1 + 2(t - 1)(1 + t + ... + t^(h-1))
  = 1 + 2(t - 1)(t^h - 1)/(t - 1)
  = 2t^h - 1.

t^h <= (n + 1)/2,
h <= log_t((n + 1)/2).
```

При `h = 0` минимальный непустой корень содержит один ключ, и итоговая формула также верна.

Максимум достигается при полностью заполненных узлах:

```text
n <= (2t - 1)(1 + 2t + ... + (2t)^h)
   = (2t)^(h+1) - 1.
```

Чем больше допустимое число детей, тем меньше высота. Но поиск и перемещение элементов внутри широкого узла тоже стоят времени. Поэтому увеличение `t` не гарантирует ускорение.

Исторически B-дерево особенно полезно для блочной внешней памяти: один узел можно размещать в одном блоке. В этой ЛР рабочее дерево можно держать в RAM; чтение диска требуется для `Save` и `Load`.

## 4. Поиск

В текущем узле найти первую позицию `i`, на которой `key[i] >= x`. Это операция `lower_bound`.

- Если такая позиция есть и `key[i] == x`, вернуть связанное значение.
- Если совпадения нет и узел — лист, ключ отсутствует.
- Иначе перейти в `child[i]`.

Если все ключи меньше `x`, получаем `i == m`: нужен последний ребёнок `child[m]`, а не `child[m-1]`.

```text
search(node, x):
    i = lower_bound(node.keys, x)
    if i < node.key_count and node.keys[i] == x:
        return node.entries[i].value
    if node is a leaf:
        return not_found
    return search(node.children[i], x)
```

В узле `[10 | 20 | 40]` поиск 25 спускается в `child[2]`, поиск 50 — в `child[3]`, а поиск 20 завершается в этом узле.

Внутри узла возможен линейный поиск `O(t)` или двоичный `O(log t)`. При малом `t` линейный поиск иногда выгоден по константам; это предмет измерений.

Сравнение строк не является бесплатным: при длинном общем префиксе оно просматривает много символов. Если максимальную длину обозначить `L`, двоичный поиск даёт `O(L log t)` на уровень.

## 5. Вставка сверху вниз

Основная идея: **не спускаться в заполненного ребёнка; сначала разделить его**. Тогда узел, в который выполняется вставка, заведомо имеет свободное место.

### 5.1. Разделение заполненного ребёнка

В заполненном узле `2t - 1` ключей. При нумерации с нуля:

- ключ с индексом `t - 1` поднимается в родителя;
- слева остаются ключи `0 .. t - 2`;
- справа остаются ключи `t .. 2t - 2`;
- у каждой половины по `t - 1` ключей.

Если узел внутренний, его `2t` детей также делятся: первые `t` переходят в левую половину, последние `t` — в правую.

```text
t = 3

До:       родитель ...
                    |
            [A | C | G | M | T]

После:    родитель ... | G | ...
                    /     \
                [A | C] [M | T]
```

В родителя переносится целая запись `(G, value_G)`. В обычном B-дереве средняя запись удаляется из ребёнка: второй копии того же ключа не остаётся.

Родитель при этом должен быть неполным. Вставка сверху вниз обеспечивает это условие заранее. После разделения родитель получает на один ключ и на одного ребёнка больше.

### 5.2. Разделение корня

Если корень заполнен, создаётся новый пустой корень. Старый становится его единственным ребёнком и разделяется. У нового корня появляется один ключ и два ребёнка.

```text
          [5 | 10 | 20]                  [10]
                                       /    \
                                     [5]    [20]
```

Высота увеличивается на один. Все старые листья отдаляются от нового корня одинаково, поэтому баланс сохраняется.

### 5.3. Общая схема

1. Нормализовать ключ.
2. Если ключ уже существует, вернуть `Exist`, не меняя его значение.
3. Разделить корень, если он заполнен.
4. В неполном узле выбрать ребёнка для спуска.
5. Если ребёнок заполнен, разделить его и заново определить, в какую из двух половин идти.
6. В листе вставить запись на упорядоченную позицию, сдвинув большие записи вправо.

Предварительный поиск дубликата — простой способ отделить проверку от изменений. Он добавляет ещё один проход по высоте, но не меняет асимптотику. Можно объединить проверку со вставкой, если тщательно обработать совпадения со всеми встреченными и поднятыми ключами.

### 5.4. Последовательный пример

При `t = 2` вставляем `10, 20, 5, 6, 12, 30, 7, 17`.

```text
10, 20, 5:       [5 | 10 | 20]

6:                    [10]
                     /    \
                 [5 | 6]  [20]

12, 30, 7:            [10]
                     /    \
              [5 | 6 | 7] [12 | 20 | 30]

17:                  [10 | 20]
                    /    |    \
             [5 | 6 | 7] [12 | 17] [30]
```

Перед вставкой 17 правый ребёнок заполнен. Поднимается 20, справа остаётся 30, слева — 12. Затем 17 вставляется рядом с 12.

## 6. Удаление сверху вниз

Основная идея: **перед спуском обеспечить ребёнку хотя бы `t` ключей**, то есть на один больше обязательного минимума. Тогда он сможет потерять одну запись, сохранив допустимое заполнение.

Разрешены три локальные операции: удалить запись из листа, перераспределить записи через родителя, слить двух соседей вместе с разделителем родителя.

### 6.1. Ключ найден в листе

Удалить запись и сдвинуть остальные влево. Если лист — не корень, алгоритм заранее обеспечил минимум `t` ключей до удаления. После удаления останется хотя бы `t - 1`.

```text
[5 | 6 | 7] -- удалить 6 --> [5 | 7]
```

### 6.2. Ключ найден во внутреннем узле

Пусть удаляем `K`, слева от него ребёнок `L`, справа — `R`.

**Случай A: в L хотя бы t ключей.** Найти предшественника `P`: максимальный ключ поддерева `L`. Он находится в самом правом листе этого поддерева. Заменить запись `K` целой записью `P`, затем рекурсивно удалить старую запись `P` из `L`.

```text
        [10]                         [7]
       /    \                       /   \
   [5 | 7] [12]        -->         [5]  [12]
```

Важно: `P` — максимум всего левого поддерева, а не обязательно последний ключ самого узла `L`.

**Случай B: в L минимум, а в R хотя бы t ключей.** Симметрично взять преемника `S`: минимальную запись всего поддерева `R`. Заменить `K` на `S` и рекурсивно удалить `S` из `R`.

```text
        [10]                         [12]
       /    \                       /    \
     [5] [12 | 17]      -->        [5]   [17]
```

**Случай C: в обоих детях по t - 1 ключей.** Слить `L`, запись `K` и `R`:

```text
(t - 1) + 1 + (t - 1) = 2t - 1.
```

Получится допустимый заполненный узел. У родителя удалить `K` и один указатель на ребёнка. Затем рекурсивно удалить `K` из объединённого узла.

```text
       [10 | 20]                    [20]
      /    |    \                  /    \
    [5]  [12]  [30]   --> [5 | 10 | 12] [30]

Затем удалить 10 из объединённого листа: [5 | 12].
```

Замена предшественником/преемником и его рекурсивное удаление образуют одну операцию. До её завершения возможна временная копия записи; наружу должен выходить словарь с единственными экземплярами ключей.

### 6.3. Ключа нет в текущем внутреннем узле

Выбрать ребёнка по обычному поиску. Если у него хотя бы `t` ключей, можно спускаться сразу. Если только `t - 1`, сначала выполнить одно из исправлений ниже.

**Заимствование у левого соседа.** Возможно, если у соседа хотя бы `t` ключей:

1. Разделитель родителя опускается в начало нужного ребёнка.
2. Максимальная запись левого соседа поднимается на место разделителя.
3. Если узлы внутренние, последний ребёнок левого соседа становится первым ребёнком исправляемого узла.

```text
До:            [10 | 20]
              /    |    \
          [5 | 7] [12]  [30]

После:          [7 | 20]
              /    |     \
            [5] [10 | 12] [30]
```

Теперь при удалении 12 можно спуститься в `[10 | 12]`; после удаления останется `[10]`.

**Заимствование у правого соседа.** Симметрично:

1. Разделитель родителя дописывается в конец нужного ребёнка.
2. Минимальная запись правого соседа поднимается к родителю.
3. Первый ребёнок правого соседа становится последним ребёнком исправляемого узла.

```text
До:           [10 | 20]
             /    |     \
           [5] [12 | 17] [30]

После:        [12 | 20]
             /    |    \
        [5 | 10] [17]  [30]
```

Если удаляем 5, после спуска получим лист `[10]`.

Передавать ключ напрямую от соседа к соседу нельзя: границу между поддеревьями задаёт запись родителя. Она должна участвовать в перестройке.

**Слияние.** Если соседям нечего отдать, нужный ребёнок объединяется с соседним и разделителем родителя.

```text
До:           [10 | 20]
             /    |    \
           [5]  [12]  [30]

После:         [20]
              /    \
      [5 | 10 | 12] [30]
```

Родитель теряет одну запись. Некорневой родитель был подготовлен перед входом в него и может это перенести. Корень имеет отдельное исключение по минимальному заполнению.

Если нужный ребёнок был последним и слит с левым соседом, индекс дальнейшего спуска уменьшается на один. Это частая ошибка реализации.

### 6.4. Уменьшение высоты

Если после удаления у корня нет ключей, но есть один ребёнок, этот ребёнок становится новым корнем. Старый пустой корень освобождается.

```text
       [10]
      /    \
    [5]   [12]

Удаляем 5: слияние даёт [5 | 10 | 12], затем удаление даёт [10 | 12].
Пустой старый корень заменяется этим листом.
```

Если корень — пустой лист, словарь пуст. Все листья при сокращении корня приближаются на один уровень одновременно.

### 6.5. Если удаляемого ключа нет

Можно сначала вызвать поиск и сразу вернуть `NoSuchWord`. Это удобно при первой реализации.

Можно искать и удалять за один проход. Тогда заимствования и слияния иногда произойдут даже при отсутствующем ключе. Форма дерева изменится, но набор пар должен сохраниться. Это допустимо для семантики словаря, однако требует аккуратного результата операции.

### 6.6. Почему удаление сохраняет свойства

При заимствовании донор содержит хотя бы `t` ключей и после передачи остаётся с минимумом `t - 1`. Получатель получает запас. При слиянии двух минимальных соседей получается ровно максимум `2t - 1`. Проход через разделитель сохраняет порядок. Изменяется содержимое узлов на одном уровне, поэтому глубина листьев не меняется. Исключение — сокращение корня, которое одинаково действует на все листья.

## 7. Сложность

Пусть `L` — максимальная длина сравниваемых слов, `h + 1` — число посещаемых уровней. При `n >= 1` высота `h = O(log_t n)`.

| Операция | Работа внутри уровня | Итог |
| --- | --- | --- |
| Поиск, линейный поиск в узле | До `O(Lt)` | `O(Lt(h + 1))` |
| Поиск, двоичный поиск в узле | До `O(L log t)` | `O(L log t(h + 1))` |
| Вставка/удаление в обычных массивах | Поиск позиции и до `O(t)` перемещений записей/детей | До `O(Lt(h + 1))` при консервативном учёте работы со строками |

Для фиксированных `t` и `L <= 256` обычно говорят `O(log n)` на словарную операцию. Если перемещения строк не копируют их символы, стоимость перестройки может быть ниже этой консервативной оценки. Нельзя выводить `O(log_t n)` полного CPU-времени только из количества уровней.

Число узлов при непустом дереве — `O(n/t + 1)`, потому что каждый некорневой узел содержит хотя бы `t - 1` ключей. Суммарная вместимость узлов — `O(n + t)`; при фиксированном `t` память линейна по числу записей плюс память строк. Незаполненные слоты, ёмкость контейнеров и накладные расходы аллокатора тоже расходуют RAM.

## 8. Порядок реализации

1. Зафиксировать представление пустого дерева и определение `t`.
2. Описать запись `(key, value)` и узел, определить владельца каждого ребёнка.
3. Реализовать поиск и проверку инвариантов.
4. Реализовать `splitChild`, затем вставку и разделение корня.
5. Проверить вставки при `t = 2`, в том числе в возрастающем и убывающем порядке.
6. Отдельно реализовать заимствование слева, справа и слияние.
7. Собрать удаление из этих операций, добавить сокращение корня.
8. Добавить нормализацию и протокол команд.
9. Добавить `Save` и `Load` во временное дерево.
10. Проверить ошибки, память и скорость; сохранить реальные результаты для отчёта.

При реализации перестроек сначала нарисовать маленький пример, затем явно указать, какие записи и дети перемещаются. Проверять инварианты после каждой законченной публичной операции. Это полезнее, чем искать ошибку только по последующему неправильному ответу поиска.

## 9. Вопросы к защите

1. **Почему это дерево поиска?** Ключи узла разделяют непересекающиеся диапазоны его поддеревьев.
2. **Почему оно сбалансировано?** Все листья имеют одинаковую глубину, а каждый некорневой узел заполнен хотя бы до `t - 1` ключей.
3. **Почему `t >= 2`?** Нужна гарантированная ветвистость хотя бы два; при `t = 1` разрешаются пустые некорневые узлы и цепочки, и доказательство логарифмической высоты перестаёт работать.
4. **Почему разделяют `2t - 1` ключей?** Один поднимается, по `t - 1` остаётся с обеих сторон.
5. **Почему при вставке родитель должен быть неполным?** В него добавляется средняя запись и дополнительный ребёнок.
6. **Почему перед удалением нужен запас?** Удаление или слияние ниже может уменьшить число записей текущего узла на одну.
7. **Почему нельзя заимствовать у минимального соседа?** У него осталось бы `t - 2` ключей.
8. **Почему слияние не переполняет узел?** В нём `(t - 1) + 1 + (t - 1) = 2t - 1` записей.
9. **Когда меняется высота?** При разделении заполненного корня и удалении пустого внутреннего корня.
10. **Почему перемещают вместе ключ и значение?** Они образуют одну запись словаря; перестройка не должна менять соответствие слова и числа.
11. **Всегда ли предшественник — соседний ключ в массиве родителя?** Нет: это максимум соответствующего левого поддерева.
12. **Почему B-дерево может быть быстрее двоичного дерева?** Оно посещает меньше узлов; фактический эффект зависит от размеров узлов, строк и поведения памяти.
